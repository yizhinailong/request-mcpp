# Version tags and Windows CI

`.github/workflows/version.yml` runs when a push to `main` changes `mcpp.toml`.
It parses `[package].version` as TOML at the push's previous and current commit,
so multi-commit pushes are compared as a whole. A version change such as
`0.1.0` to `0.2.0` creates the lightweight tag `v0.2.0` at that push's final commit.
Changes to dependencies, descriptions, formatting, or comments do not create
tags when the package version stays the same. Initial branch/manifest creation
establishes a baseline without a tag.

Existing tags are never overwritten. Reusing a version tagged at a different
commit fails the workflow; choose an unused version. Retrying the same push
reuses its existing tag and runs Windows tests again. No commit, version bump,
or GitHub Release is generated by these workflows.

After publishing the tag, the version workflow calls
`.github/workflows/windows.ci.yml` and passes the complete tag ref. This is
necessary because pushes made with `GITHUB_TOKEN` do not start new push
workflows, as described in the
[GitHub triggering documentation](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow).
The Windows workflow also handles `v*` tags pushed by users. Ordinary branch
pushes and pull requests do not start Windows tests.

The Windows job checks out the tag, installs the checksum-pinned official
`mcpp` Windows release `2026.9.11.1` into the runner's temporary directory,
installs and selects `llvm@22.1.8`, and runs `mcpp build` followed by `mcpp test`. The hosted
Windows image supplies the Visual Studio/Windows SDK installation required by
the LLVM MSVC target. Update the version and checksum together in
`.github/scripts/install_mcpp.ps1` when upgrading mcpp.

Only the tag job requests `contents: write`; Windows tests use read-only
repository access. The built-in token is sufficient, with no additional secret
required. Repository rules must allow that job to create version tags. A failed
Windows test leaves the tag in place and marks the workflow as failed; rerun
the failed job after investigating.

Local validation:

```sh
python -B -m unittest discover -s .github/scripts -p 'test_*.py'
actionlint .github/workflows/version.yml .github/workflows/windows.ci.yml
mcpp test
```

The Python tests push tags only to disposable local bare repositories.
